It is designed as an onboarding reference for new team members and a daily quick-reference for the whole team.

---

## About OctoAcme's Project Management Approach

OctoAcme operates a structured, lifecycle-based project management approach that prioritizes customer value, iterative delivery, and clear ownership. The process flows through five distinct phases: **Initiation** (validating business need and stakeholder alignment), **Planning** (breaking work into shippable increments with defined acceptance criteria), **Execution** (day-to-day delivery with regular reviews), **Release** (standardized deployment with risk mitigation), and **Close & Retrospective** (capturing learnings for continuous improvement).

The organization defines clear roles and responsibilities across three primary personas: **Product Managers** who own the vision and prioritize the backlog; **Project Managers** who coordinate schedules and manage risks; and **Developers** who implement features while contributing to design and testing.

Quality assurance and risk management are woven throughout execution. The team uses a GitHub Projects workflow, enforces automated CI testing and security scanning, and escalates blockers through a three-level escalation path. The Risk Register is maintained as a living artifact, updated weekly during syncs.

OctoAcme embeds continuous improvement into its operating rhythm through structured retrospectives held after each sprint, release, or milestone, converting learnings into numbered action items tracked in the project backlog.

## Project Lifecycle Quick Reference

```
Initiation → Planning → Execution → Release → Close & Retrospective
```

| Phase | Key Activities | Primary Owner |
|---|---|---|
| **Initiation** | Define problem statement, validate business need, align stakeholders, create Project Charter | Product Manager |
| **Planning** | Break work into increments, define acceptance criteria, estimate and prioritize backlog | Product Manager + Project Manager |
| **Execution** | Deliver features, run standups, update board, manage risks, review PRs | Developer + Project Manager |
| **Release** | Pre-deployment checklist, smoke tests, staged rollout, rollback plan | Project Manager + Developer |
| **Close & Retrospective** | Capture learnings, create action items, archive project artifacts | Project Manager + Full Team |

## When and How to Use Each Document

- **Starting a new project?** Begin with [Project Initiation](octoacme-project-initiation.md) to ensure the business need is validated and stakeholders are aligned before any planning begins.
- **Building the roadmap or sprint plan?** Use [Project Planning](octoacme-project-planning.md) to structure the backlog with shippable increments and clear acceptance criteria.
- **Tracking daily work?** [Execution and Tracking](octoacme-execution-and-tracking.md) describes the GitHub Projects board columns, standup format, PR guidelines, and how to escalate blockers.
- **Managing risks or communications?** Refer to [Risks and Communication](octoacme-risks-and-communication.md) for the Risk Register template, communication cadences, and escalation path.
- **Preparing for a release?** Follow the checklist and steps in [Release and Deployment](octoacme-release-and-deployment.md) to reduce production risk.
- **Running a retrospective?** [Retrospective and Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md) provides the session format and action item tracking process.
- **Understanding team roles?** [Roles and Personas](octoacme-roles-and-personas.md) clarifies responsibilities for each team member type.
- **Need the big picture?** The [Project Management Overview](octoacme-project-management-overview.md) covers the full framework and its guiding principles.
